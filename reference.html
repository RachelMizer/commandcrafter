Bedrock Edition

Reference

Bedrock syntax only. Java Edition commands differ in ways that look small and fail silently, so anything copied from a Java tutorial usually needs rewriting.

Coordinates

AxisPositiveNegative
XEastWest
YUpDown

Tilde: relative to you

A tilde means "measured from where I am standing".

~Your position on that axis
~1One block further along
~-1One block back — the block below you, on Y
~ ~-1 ~The block you are standing on

Caret: relative to where you look

^left ^up ^forward — rotates with your view rather than the compass. ^ ^ ^3 is three blocks in front of your face whichever way you turn.

/fill

/fill <x1 y1 z1> <x2 y2 z2> <block> [data] [mode] [replaceBlock] [replaceData]
ModeWhat it does
replaceSolid fill. The default when no mode is given.
outlineWalls, floor and ceiling only. Leaves the inside alone.
hollowSame shell as outline, but clears the inside to air.
destroyBreaks the old blocks properly so they drop as items.
keepOnly fills air. Nothing already placed gets touched.

Common shapes

/fill 607 62 1238 619 62 1247 grass_block
/fill ~ ~ ~ ~10 ~5 ~10 stone_bricks hollow
/fill ~-1 ~-1 ~ ~-1 ~-33 ~ stone_bricks     (a tall thin column)
/fill 978 71 927 961 70 938 air             (clear it out)

Replacing one block type

The data value in front of replace is positional — the command will not parse without it. If the block only comes in one variety, that number is 0. 

/fill <x1 y1 z1> <x2 y2 z2> stone 0 replace cobblestone 0
/fill 105 63 114 49 70 189 air 0 replace tall_grass

Newer versions accept block states instead, and they read better than remembering which number means "mossy": 

/fill ~ ~ ~ ~10 ~4 ~10 stone_brick["stone_brick_type"="mossy"]

Size limit. /fill and /clone both stop at 32,768 blocks (32 × 32 × 32). Bigger jobs have to be split — stepping the Y range a few layers at a time is usually the least confusing way.

/clone

/clone <x1 y1 z1> <x2 y2 z2> <destination> [maskMode] [cloneMode] [block] [data]

The destination is the lowest north-west corner of where the copy will sit — smallest X, smallest Y, smallest Z. Getting this wrong is the usual reason a build lands somewhere unexpected.

Mask modeWhat it does
replaceCopies everything, air included. Default.
maskedSkips air, so the copy drops onto existing terrain.
filteredCopies one named block type and nothing else.
Clone modeWhat it does
normalLeaves the original where it is. Default.
moveDeletes the original, leaving air. The building moves.
forceAllows the source and destination to overlap.
/clone 100 64 100 110 74 110 200 64 200
/clone 100 64 100 110 74 110 200 64 200 masked
/clone 100 64 100 110 74 110 200 64 200 replace move

Selectors

SelectorWho it means
@pNearest player
@aAll players
@eAll entities — players, mobs, items, frames, everything
@sWhoever is running the command
@rA random player

Arguments

type=cowOnly cows. type=!player means everything but players.
tag=vipHas that tag. tag=!vip for those without it.
r=20 / rm=5Maximum and minimum distance
c=1Limit to this many, nearest first
name="Mac"Matches the entity's name
x= y= z= dx= dy= dz=A box, starting at x/y/z and running dx/dy/dz blocks
scores={Coins=10..}Score is 10 or more
hasitem={item=coal,quantity=1..}Carrying at least one coal

dx/dy/dz are sizes, not the far corner. x=100,dx=10 covers X 100 to 110. Putting the second corner's coordinate in there selects a region far bigger — or entirely elsewhere — than you meant.

Ranges

10..10 or more
..99 or less
5..10Between 5 and 10
12Exactly 12 — rarely what you want for a price check

For a price of 10, the two branches are Coins=..9 and Coins=10... An exact Coins=10 means anyone with 11 coins can't buy it.

NPCs and dialogue

Making one

Get an NPC spawn egg from the creative menu, or with /give @p spawn_egg 1 51. Place it, then right-click to open the NPC editor and set its name and dialogue. Left-click removes it.

Tag it so commands can find it — stand looking at the NPC and run:

/tag @e[type=npc,c=1] add mac

Moving between scenes

/dialogue open @e[tag=mac] @initiator
/dialogue open @e[tag=mac] @initiator macbuy

Ordering inside a dialogue button

Every command on the button runs top to bottom against a selector that is re-evaluated each time. Anything that changes whether the player still matches has to go last:

  • Charging coins before giving the item means the item never arrives.
  • Clearing the item before paying means the payment never arrives.
  • Removing the tag before the rewards means the rewards never arrive.

Sounds

/playsound <sound> <player> [x y z] [volume] [pitch] [minVolume]

Bedrock uses its own sound IDs — random.orb, mob.villager.haggle, mob.cow.say. The Java-style entity.villager.trade names do not exist here, and Bedrock has no sound-category argument, so a Java command like playsound minecraft:entity.cow.ambient master @s fails twice over.

Scoreboards

/scoreboard objectives add Coins dummy "Coins"
/scoreboard objectives setdisplay sidebar Coins
/scoreboard players add @a Coins 0        (registers players without touching scores)
/scoreboard players add @p Coins 5
/scoreboard players remove @p Coins 5
/scoreboard players set @p Coins 0
/scoreboard players reset @p Coins
/scoreboard objectives remove Coins

add @a Coins 0 is the safe way to put everyone on the board: it creates an entry for anyone missing and changes nothing for anyone already there. set would wipe existing balances.

Command blocks

TypeWhen it runs
ImpulseOnce, each time it gets powered
RepeatEvery tick while active
ChainAfter the block pointing into it runs
SettingMeaning
ConditionalOnly runs if the block before it succeeded
UnconditionalRuns regardless
Always ActiveNo redstone needed
Needs RedstoneWaits for a signal

A chain fires in the direction the block faces, so the arrow on each block has to point at the next one. A typical trigger is Impulse + Needs Redstone at the front, followed by Chain + Unconditional + Always Active for the rest.

Firing a chain from a dialogue button

Dialogue buttons can't summon at a player's position, so they place a redstone block instead and let command blocks take over. The last block in the chain clears the redstone so the trigger can be used again. 

/setblock -293 57 -320 redstone_block     (button fires it)
/setblock -293 57 -320 air                (last chain block resets it)

/execute

/execute as <target> at @s run <command>
/execute as @a[tag=buyer] at @s run summon cow ~ ~1 ~

as changes who runs the command, at changes where it runs from. You usually want both — as @a[...] at @s — otherwise ~ ~ ~ means the command block's position, not the player's.

Things that quietly go wrong

  • /kill @e with no type kills you as well. Always add a type, or type=!player.
  • dx/dy/dz are region sizes, not the second corner.
  • Exact scores like Coins=12 exclude anyone with 13.
  • Charging before rewarding stops the player matching the selector partway down a button.
  • Java sound names and the master category argument don't exist in Bedrock.
  • Objective and tag names with spaces break selector syntax. Use underscores.
  • hollow needs at least 3 blocks on every side to have an inside to clear.
  • Command blocks need cheats enabled, and on a realm, operator permissions.
